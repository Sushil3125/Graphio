# Explained differences: Java (PSI) analyzer vs golden Python analyzer

`tools/graphdiff.py --explained bench/DIFFERENCES.md` reads this file. Each entry allows one
(or, with patterns, several) golden-vs-candidate differences that would otherwise fail a gate.
Every entry **must** carry a reason after `: ` (entries without one are ignored with a warning).

Entry formats (only lines starting with `- ` outside code fences are entries):

```
- <kind> <source> -> <target>: <reason>     golden edge allowed to be missing from the candidate
- entrypoint <node id>: <reason>            entrypoint allowed to be missing / extra / different
```

* `<kind>`, `<source>`, `<target>`, `<node id>` are `fnmatch` patterns (`*`, `?`, `[...]`), matched
  case-sensitively against edge kind and node ids (`<module>:<qualname>`), e.g.
  `- calls sqlalchemy.orm.* -> sqlalchemy.util.langhelpers:*: golden followed a wrong re-export`.
* A `## <project>` heading (the graph's `project` field: `gis_api`, `fastapi`, `celery`,
  `sqlalchemy`) scopes the entries below it to that corpus; entries before any heading, or under
  `## all`, apply to every corpus.
* Only gated edge kinds need entries (`calls`, `depends`, `instantiates`, `inherits`,
  `includes_router`, `routes`); `references` / `implements` differences and extra candidate edges
  are reported, never failures. Entries that match nothing are listed as possibly stale.
* Prefer one entry per edge with a concrete reason ("golden was wrong: `x.f` is shadowed by the
  local assignment on line 12"); use wildcards only for a whole, understood class of difference.
